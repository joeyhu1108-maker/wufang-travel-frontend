# 预订与支付全流程演示 · V2.2

## 如何演示

首页右上角、手机底栏或路线概览处点击「选团期」。

1. 在 10 天阿里大环线和 13 天冈仁波齐转山环线之间切换。
2. 选择固定团期，或切到「自己定日期」。左右箭头可浏览当前月及未来两个月。选择的是拉萨集合／抵达日，返程日自动加上路线天数；因此包含 1 天独立抵达日及 10／13 天路线。
3. 选择同行人数。固定团期含可选、已满及无团期状态，人数上限随示例余位变化；换到余位更少的日期会提示并调整人数。
4. 出行信息页点击「一键填入演示信息」。也可以留空或输入不完整的手机号，查看逐项错误提示。请勿使用真实个人资料。
5. 在确认页核对日期、称呼、人数、金额；可以返回修改。需勾选已了解演示说明，才能创建演示订单。
6. 选择微信或支付宝，再进入模拟收银台。分别体验「模拟支付成功」「模拟支付失败」「取消本次支付」。没有可扫描的真实收款码，不要求密码或账户，不唤起支付 App。
7. 支付失败或中途取消后，订单仍为待支付，可以重试或稍后支付。只有「模拟支付成功」将订单改为已模拟支付，实际扣款为 ¥0。
8. 从「我的订单」按全部／待支付／已模拟支付／已取消筛选。刷新可恢复待支付订单并继续付款；待支付订单可二次确认后取消。已支付或已取消订单不能再次支付。

## 演示数据规则

- 以中国时区的当前日期为基准，开放至少 3 天后的日期，至第三个展示月月末。规则用于长期可演示，不代表未来真实排期。
- 固定团期：10 天路线每月 8、15、22、29 日；13 天路线每月 6、13、20、27 日。日期存在且满足窗口才显示可选。四个日期对应示例余位 4、0、2、6；余位不会被演示订单扣减。
- 自选日期：窗口内日期均可选择，最多 6 人；模拟包团意向，是否成行需另行确认。
- 演示单价：10 天路线 14,800 元／人，13 天路线 18,800 元／人。统一使用整数分计算，全款支付，不模拟真实优惠或补差规则。
- 新订单为 `pending`；模拟支付成功转 `paid`；取消未支付订单转 `cancelled`。支付失败／取消本次支付不取消订单。
- 最多保存最近 30 笔订单；没有真实订单锁位、超时关闭或跨设备同步。

## 数据与迁移

`booking.mjs` 为不依赖 DOM 的日期、校验、计价和状态纯函数，可随数据模型迁移；`booking-ui.js` 负责 DOM 与历史导航。沿用 HTML、CSS、JavaScript ES Modules，不引入平台 SDK 或新的运行时依赖。

`localStorage` 的 `wufang-demo-orders-v1` 仅保存演示订单号、路线、日期、人数、金额、状态、时间和模拟渠道。出行人、联系人、手机号、备注不保存、不上传；关闭弹窗可保留本次未提交草稿，刷新页面会清除。若浏览器拒绝存储，当前页仍可演示，但刷新后可能丢失记录。

## 真正上线前需要补齐

- 品牌确认的团期、库存、价格、服务包含／不包含、酒店车辆、正式合同与退改条款。
- 服务端订单与库存接口、可信报价计算、真实联系人数据的合规收集与权限管理。
- 商户资质、支付渠道接入、服务端签名与回调验证、幂等处理、支付状态查询、退款与对账。
- 用户身份、跨设备订单查询，以及甲方目标手机／微信浏览器的真机验收。

前端演示不代表这些服务已接入。不要以本地状态或前端按钮结果决定真实资金或出行安排。

## 验证方式

`npm run verify` 运行 23 项纯函数／导航测试、构建与资源检查。浏览器测试脚本是 `scripts/qa-booking.mjs`，需要另外提供 Playwright 与 Chromium；它们不是网站运行依赖。可用 `PLAYWRIGHT_MODULE` 指定 Playwright 模块位置、`CHROME_BIN` 指定 Chrome 路径，`QA_ROOT_URL`／`QA_SUBDIR_URL` 指定根目录与子目录测试地址。

浏览器测试覆盖 1440 × 1000、390 × 844、320 × 740，阻止所有非本机网络请求，保存截图与 `qa-output/booking-results.json`。这不是微信或 iPhone 真机验收。
