# 无方旅行移动端设计 / 交互原型

## 这是什么

这是一个可点击、可走通流程的移动端设计原型，范围只包含信息结构、交互和 UI：

`发现 → 路线 → 详情 → 团期 / 人数 → 出行信息 → 核对 → 模拟支付状态 → 我的行程`

原有 H5 未修改。本原型不连接登录、库存、订单、退款、客户资料或真实支付，也不会产生真实订单。

## 参考与证据边界

甲方提供的两个走之旅行小程序分享入口在当前环境无法直接打开，因此没有把未核实页面当成事实。第一版依据此前录屏中可见的结构（首页路线入口、筛选、路线详情、团期日历、费用说明、同行人、订单状态）以及无方已有路线素材整理；无法确认的内容均以「参考价 / 演示数据 / 需确认」标注。

## 页面与关键交互

- 发现：首页品牌入口、区域影像、当季路线、旅途短文弹层。
- 路线：关键词搜索、慢旅行 / 转山徒步筛选、收藏、路线卡片。
- 详情：这一路 / 逐日行程 / 出发前三个信息层级；费用与边界、找搭子、分享弹层。
- 团期：月份切换、可用日期、余位展示、同行人数加减、参考费用汇总。
- 出行信息：姓名与手机号校验，一键填入虚构演示信息。
- 核对：再次确认路线、日期、人数和参考费用，并明确“不是购买或支付”。
- 支付状态：仅模拟成功 / 取消，展示状态页和本地演示编号。
- 我的行程：展示本地演示记录和收藏路线。

## 本轮借鉴 Airbnb 的部分

借鉴的是可迁移的产品机制，而不是复制品牌视觉：

- 把搜索拆成目的地、日期、人数三段的渐进式搜索胶囊，降低第一次选择的压力。
- 用全屏抽屉承载更多筛选，把路线类型和偏好放在同一处完成，再一次性应用。
- 给路线列表增加地图视角入口，让“路线”与西藏的地理距离建立关系。
- 在详情页提供固定底部行动栏，让用户在长内容中始终知道下一步是什么。
- 用收藏、分享和可回看的“我的行程”形成轻量计划回路，不要求用户立即购买。
- 页面切换、抽屉进入、收藏反馈和成功状态均加入短时、克制的动效，并遵守 `prefers-reduced-motion`。

这些模式参考 Airbnb 官方帮助中心公开描述的目的地 / 日期 / 人数搜索、筛选、地图与心愿单机制；无方版本仍保留“先咨询、再确认”的业务边界。

## 设计系统与组件化

本轮将移动端原型拆成两层：

- `design-system.css`：颜色、间距、圆角、动效时长、触控尺寸和 reduced-motion 约束。
- `components.mjs`：`icon`、`heroHeader`、`navMarkup`、`routeCard` 四个无框架渲染组件；组件只输出语义 HTML，后续可以平移到 Vue、React 或小程序模板。

页面业务逻辑仍保留在 `ui.js`，这样路线数据、交互状态和视觉组件彼此分离，便于甲方后续补真实团期、订单和支付接口。

### 图标与品牌资产

- 顶栏分享使用标准三节点分享图标；斜向箭头仅用于“查看路线 / 继续”这类前进动作。
- 首页与支付页均调用现有无方 SVG 资产，不重绘、不改色、不替换为第三方 Logo；CSS 只控制容器尺寸与留白。

## 视觉方向

采用「高原旅行手册」方向：纸白、岩灰、藏蓝与陶土红作为主色；保留无方最终锁定的黑色标识，同时用雪山、湖岸、土林等区域影像建立西藏感。版式以大留白、衬线标题、窄字宽数字和克制的分割线建立高级感，避免旅游平台常见的促销卡片堆叠。

## 需要甲方补充后才能进入真实产品

真实上线前仍需补齐：可售团期 / 价格 / 余位；费用包含与不包含；住宿、用车、餐食标准；取消改期退款规则；集合与返程信息；客服、服务二维码；用户协议、隐私政策和高原出行提示；图片与字体授权；登录、支付、订单、通知及后台接口权限。

## 本地预览与验证

在项目目录执行：

```bash
npm run dev -- --port 4178 --strictPort
```

打开：`http://127.0.0.1:4178/mobile-design/index.html`

构建与现有项目回归检查：

```bash
node --check public/mobile-design/ui.js
npm run verify
```
