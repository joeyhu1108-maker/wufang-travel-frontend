# 接口、订单与资金｜实现边界

## 已编写的接口

小程序仅调用云函数 `wufangApi`：`{ action, payload }`。

成功：`{ ok: true, data }`；失败：`{ ok: false, code }`。失败不得显示保存／登录／付款成功。超时不会取消服务端执行，因此咨询重试保留同一个幂等键。

| action | 输入 | 成功输出 | 边界 |
| --- | --- | --- | --- |
| `login` | 无 | `authenticated: true, user: { id }` | 身份来自服务端微信上下文；不等于手机号授权或用户资料注册完成 |
| `listRoutes` | 无 | 已批准且资料完整的路线数组 | 无实时团期库存 |
| `getRoute` | `id` | 对应路线 | 无效／下架 ID 不回退到其他路线 |
| `createInquiry` | `routeId, requestId, name, phone, date, people, consent, privacyVersion` | `id, status: received` | 只保存咨询，不占库存，不生成付费订单 |

前端身份／价格／routeTitle／owner／支付状态均不可信。咨询仅接受中国大陆 11 位手机号、1–6 人、当天或之后的有效日期、已确认隐私版本；这些是本期咨询规则，不自动适用于交易人数或境外用户，扩大范围需确认。

同身份同键同内容只一条记录；改内容复用键返回冲突；同身份一分钟内另一新键被限流。限流写入与咨询持久化失败可能先占限流槽，同键允许恢复重试。当前实现只有单身份限流，仍需云平台级防滥用与监控。

当前云函数 SDK 未通过发布安全门槛，这些接口仍需要真实环境联调。

## 交易功能未实现：以下是待实施与待验收规范

绝不能将规范当已实现 API。

### 服务端领域数据

- 路线：授权内容及上下架。
- 团期：真实未来起止日、路线版本、领队、总名额、线下已确认、成团条件、价格与规则版本。
- 金额：订单使用整数“分”，服务端算总价／定金／单房差；存价格快照，不信任客户端总额。当前路线展示价是整数“元”，交易实现时明确转换，避免 100 倍金额错误。
- 库存：可售 = 总名额 − 线下确认 − 线上已确认 − 未到期锁定。不能直接维护“余位”字符串或允许为负。
- 订单：可信用户、团期与价格快照、旅客信息、订单状态、锁定截止时间、商户订单号及审计轨迹。
- 支付／退款事件：服务端唯一业务键、平台交易号、已付金额、已退金额、验签及处理结果。

### 预订与支付

```text
选择真实团期 → 服务端校验人数／价格／库存
       ↓ 事务检查并锁定名额 30 分钟
待支付订单（快照不可被客户端改写）
       ├─ 取消／到期 → 释放锁定（仅一次）
       └─ 申请微信支付参数 → 微信收银台
                    ↓
       服务端通知验签 + 商户／AppID／金额核对
                    ↓
          事务确认订单、名额和支付记录
                    ↓
          客户端主动查单显示真实结果
```

`wx.requestPayment` 的前端回调不作为最终已付款依据。关闭收银台后查单，网络异常显示“确认中”，不可立即把客户当未付款再次扣款。

必须覆盖：最后一个名额并发、线下人数变更不能超售、重复通知、延迟通知、服务中断恢复、金额／商户／AppID 不符、订单到期但已收款的冲突处理。最后一种不得简单丢回调，应按经确认业务策略恢复有效订单或退款并告警。

### 退款

用户申请 → 运营审核 → 服务端全额／部分原路退款 → 平台结果确认 → 订单／名额处理 → 客户通知与对账。

- 不允许客户端直接改“已退款”或指定任意退款金额。
- 同审批事件仅一次，累计退款不超过实付；保留平台退款号与审批记录。
- 全取消后按规则释放名额；部分退款不能自动当作全部退团，只释放明确取消的旅客名额。
- 退款申请、处理中、成功、失败及人工跟进需要明确状态。客户政策与支付通道规则由甲方确认。
- 定金与尾款策略先确认，不能临上线再猜。若本期只全款，需双方书面确认减少范围。

### 后台与权限

本期一个运营管理角色不等于“登录的人都能管理”。服务端白名单／可信角色验证，任何变更记录操作者、前后值、时间、原因。旅客用户、客服与管理动作不能只靠页面隐藏隔离。

运营可维护路线与团期、线下报名、内容审核、退款审批；线上占用、价格快照及资金结果由服务端计算，不提供手工随意覆盖按钮。

### 社区及外链

团友投稿：本人草稿 → 内容检查 → 待团队审核 → 审核公开。公开数据与私有原稿分离；本人可撤回，举报与删除有人处理。不存在为了演示而伪造已审核的旅客评价。

小红书需求是**微信内的目标小程序**。拿到准确 AppID 与 pagePath 后验证跨小程序跳转；H5 URL 不等于可跳转的小程序地址。若不支持目标页，应说明限制并提供经确认的替代路径，不能保证任何链接都能跳。

公众号活动需要准确文章地址与主体／域名许可。所有外链及支付相关域名在正式配置开启校验后验证；不依赖开发者工具关闭合法域名检查。
