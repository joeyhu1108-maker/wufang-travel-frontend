# 无方移动端 · 账号与支付交付边界

更新时间：2026-09-16。当前交付为可操作的 HTML/CSS/JavaScript 移动端原型，不是已上线小程序，不创建真实账号、订单或扣款。

## 已实现

- 我的行程 → 登录 / 注册 → 手机号校验 → 验证码 → 注册昵称 → 登录态 → 退出。
- 本地体验号码 `13800000000`、验证码 `246810`；不发送短信。会话仅保存演示昵称与 demo 标记，不保存手机号、验证码或鉴权令牌。退出后清除演示身份；没有跨设备账号。
- 团期 / 人数 → 联系信息 → 核对订单 → 支付 → 结果 → 订单详情 → 我的行程。
- 支付成功、用户取消、支付失败、结果确认中四条分支；未付款订单可继续支付或二次确认取消。

- 请求处理期间禁用提交按钮；支付控制器防止并发调起。结果优先于客户端回调，以适配器查单为准。

订单仅在当前页面运行期间保留，刷新会重置；只展示最近一笔演示订单。真实持久化、跨设备订单列表、游客订单认领、退款售后、库存锁定和订单超时关闭未接入。

## 正式支付适配器契约

`createPaymentFlow(adapter)` 只依赖以下三个异步方法：

```js
adapter.preparePayment(orderId) // 服务端验证订单归属 / 金额 / 状态，返回微信预支付参数
adapter.requestPayment(parameters) // 小程序平台层调用 wx.requestPayment；取消规范化为 code: PAYMENT_CANCELLED
adapter.queryOrder(orderId) // 服务端查询并返回规范化订单状态，不能相信客户端传入的付款结果
```

页面另外调用 `createOrder({ route, date, people })` 和 `cancelOrder(orderId)`。上线时需要扩展成正式业务请求（含服务端身份、联系人引用、产品版本和幂等键），并确认以下边界：

1. 服务端按产品 / 团期重新计算整数分金额，验证身份、订单归属、库存、价格及协议版本；客户端金额不可信。
2. `createOrder` 幂等与支付幂等必须在服务端实现；前端防连点不等于后台防重复下单。
3. `preparePayment` 返回 `timeStamp / nonceStr / package / signType / paySign` 等签名参数；密钥、商户证书、签名计算不放进前端。
4. SDK 成功回调不作为到账凭据。商户后端验签处理支付通知，并查单核实金额、商户与订单一致；网络失败保持确认中，支持恢复查询。
5. 取消未支付订单时，后端先查单并正确关闭支付单，再释放库存；与支付到账并发时不可错误取消已付款订单。
6. 认证态由服务器核验；小程序登录与手机号授权是不同能力，不以本地 demo 标记当登录。账号协议、隐私政策和信息收集说明需甲方确认后接入。
7. 真实费用包含项、退改政策、旅行服务合同、履约方式和所需资质须确认。当前说明页保留「待甲方提供」的内容，不伪造已生效合同。

订单规范化状态：`pending`（待付）、`confirming`（结果未确认）、`paid`（后端核实已付）、`cancelled`（后端确认已关闭）。微信侧的处理中、未知或查询失败不能直接映射成已付 / 已取消；退款状态另行实现。

官方依据：[微信支付小程序开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4012791911)、[小程序调起支付](https://pay.wechatpay.cn/doc/v3/merchant/4012791898)。
