## 审核资料包

- 真实 AppID、企业主体、认证、服务类目、对应资质及备案状态；由管理员在平台核实。
- 名称、简介、头像（既定 Logo）、客服与投诉路径、可访问的隐私说明。
- 原生体验版本号、变更记录、操作说明、主要页面截图；截图必须来自真实原生版。
- 审核可走的完整路径与合规测试环境安排，不创建绕过权限的“万能账号”。
- 路线／团期／价格与运营批准记录，商户绑定与支付权限。[微信支付 AppID 绑定说明](https://pay.wechatpay.cn/doc/v3/merchant/4013289251)
- 原生隐私指引及需要的能力声明、合法域名（如实际使用）与访问验证。
- 甲方体验验收及明确送审授权。不要未确认就替客户提交未完成页面或隐藏功能。

建议审核操作说明（功能实装后才能使用）：

> 无方旅行提供旅游路线介绍、真实团期选择、预订支付、订单及退款申请、经团队审核的团友内容与路线探索。审核可从首页进入路线，选择已上架团期，阅读报名条款后预订；交易由绑定商户处理。探索与社区可独立浏览，投稿在审核前不公开。客服和隐私说明可从“我的”进入。

这段不是当前功能状态声明。代码未完成前不能原样送审。实际审核细节与资格以当日平台要求为准。

## 提交及发布顺序

1. 完整代码与资料确认；运行 `npm run verify`、`npm run check:miniprogram`、`npm run check:release`。
2. 记录源码版本／构建时间／云环境／规则／依赖锁文件与配置清单，不把秘密写进版本库。
3. 开发者工具真实编译、上传开发版本，设体验版，邀请甲方及测试者。
4. 完成上表用例，保留脱敏证据；更新 `acceptance.json`。本地测试结果不能作为“真支付已通过”。
5. 甲方验收该版本并授权送审；由被授权人员提交。微信可能退回或要求补资料，审核耗时不承诺固定天数。
6. 审核通过不自动等于发布，核对生产后端、正式数据、权限、账单、客服与审核值班，再由甲方确认发布。
7. 发布后立即检查核心浏览、团期、登录、预订、支付查单、退款申请和投稿；监控异常，不重复进行真实付款。

## 回滚与应急

- 保留上一个已验证源码和云函数版本、数据库规则与配置快照，数据迁移优先向后兼容；先在隔离环境演练恢复。
- 小程序前端回退使用平台允许的版本管理功能，按实际权限与版本状态操作，不承诺随时一键回滚。
- 支付／库存异常：停止新交易入口并告警，保留查单、通知处理、退款与客服；不能清空订单或直接删库“恢复”。
- 社区违规：先下架相关公开内容、保留必要审计，避免暴露私有稿件；处理举报人反馈。
- 云故障：说明暂时不可提交，表单可重试；不切到假数据继续收款。
- 恢复后按订单／交易号对账，确认名额与已付／已退金额，再开放交易。

每日查看付款异常、待处理退款、名额冲突、待审核与举报；首周复盘，首月复核账单、备份和真实流程痛点，再决定是否增加更复杂工作台。运营维护范围以最终合同确认，不把平台费用与开发费混为一谈。
