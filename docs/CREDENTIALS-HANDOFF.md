# 凭证配置与安全交接

更新：2026-10-06。本文件只说明需要什么、由谁配置、配置在哪里；不包含任何密钥。品牌 VI 合同、报价和商业条款不随本仓库公开。

## 公开信息与秘密分开

| 项目 | 当前状态／用途 | 交接方式 |
| --- | --- | --- |
| 小程序 AppID | 已在 `miniprogram/project.config.json` 配置；AppID 不是密钥 | 可以在源码中保留；仍需管理员核对主体和开发权限 |
| 云环境 ID | `miniprogram/config.js` 三个环境目前为空；环境 ID 不是密钥 | 获授权后填写正确环境并隔离开发／正式数据 |
| 云函数 WUFANG_APP_ID、WUFANG_PRIVACY_VERSION | 与真实 AppID、已确认隐私版本一致；不是商户秘密 | 在客户云环境中配置，完成联调再记录结果 |
| 小程序 AppSecret | 当前源码中的微信云上下文登录不要求把它写入客户端 | 管理员轮换及受控服务端配置；先确认接入方案是否真的需要，不为交接复制到 Git |
| 代码上传私钥 | 本机做过格式检查，未证明微信授权／白名单 | 管理员安全提供，或按平台规则生成受控上传凭证；仅本机／CI 秘密存储 |
| 腾讯云 SecretId／SecretKey | 当前没有交接完成或云授权证据 | 邀请开发成员并最小授权，确需自动化时使用受限凭证；不共享管理员主密钥 |
| 微信支付 API v3 密钥、商户私钥／证书等 | 商户尚未接通；不是小程序上传私钥 | 商户授权人按选定支付方案在受控服务端配置，不放前端、客户端、Issue 或公开 Git |

此前可能暴露的凭证需管理员确认轮换，旧值不要继续转交。记录“轮换完成”必须有实际确认；目前没有该完成证据。AppID／手机号模板／演示验证码不等于秘密，但也不能拿演示身份授予真实权限。

## Shawn 接手步骤

1. 接受 GitHub Write 邀请；甲方另外在微信／腾讯云中邀请 Shawn 的个人身份并授予必要权限。GitHub 写权限不会产生平台权限。
2. 先确定实际需要的凭证。优先成员授权，不给不需要的 AppSecret、管理员密码、原始浏览器会话或商户主权限。
3. 密钥通过双方确认的私密渠道／受控凭证管理器交接；收件身份核对后再交。不要以公开仓库、Issue、PR、聊天截图或未加密网盘为渠道。
4. 本机上传私钥保存在源码目录外、权限 600；根目录 `.wechat-ci.local.json` 只引用私钥路径，自己也设为 600。该配置和 `.env*`／`*.key`／`*.pem` 都被 Git 忽略。
5. CI 私密凭证使用受控 Secret 配置与最小访问权限；不将秘密编码为 base64 后提交（编码不是加密）。日志、错误、构建产物不得打印或嵌入密钥。
6. 核对 AppID、目标环境、白名单、开发预览授权和工具依赖风险，保留原有保护。仅凭私钥有效不代表能上传。
7. 用获授权的开发环境完成测试，再记录配置责任人、用途、轮换／撤销安排与脱敏证据。公开文档只写状态，不写值。

本轮未替用户发送任何私钥，也未创建新的私密凭证交接渠道。需要实际安全交接时，由甲方管理员和 Shawn 确认渠道及权限，不把“已写说明”当成“密钥已收到”。

## 如果误提交秘密

立即暂停相关发布并联系凭证管理员，优先撤销／轮换泄露凭证，再核对访问记录、日志、构建产物和衍生访问权限。删除当前文件或改成私有不能撤回他人已经克隆的内容；Git 历史清理需要单独评估与授权，不能以删除一行宣称风险解除。

本仓库保持 PUBLIC，因此真实密钥不进入任何提交或公开协作消息。原生／云部署门禁仍须按 [上线准备包](../launch/README.md) 执行。
