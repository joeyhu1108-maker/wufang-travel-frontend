## 保留的产品／设计方向

1. 不重做品牌。沿用最终 Logo 完整原稿 `wufang-lockup-final-v1-transparent.svg`，不重新绘制、不用字体拼出替代标识。
2. 简约移动端视觉，借鉴 Airbnb 的易用动线；藏地元素服务于内容，不堆装饰。按钮、可点击入口、选中／加载／失败状态要明显。
3. 主导航保持四个入口：发现、路线、探索、我的行程；社区作为显眼的二级入口，不擅自增加第五个 Tab。原生目前只有三个 Tab，尚未对齐。
4. 探索入口要突出：路线漫游与 3D 分卡片进入，滚动叙事；文案通俗，用户能看懂点哪里、会看到什么。
5. 社区已确认的方向是「团友投稿 → 团队审核 → 公开」。首版不做无需审核的即时公开社区。
6. 活动 Banner 可关联正式活动／公众号内容。小红书需求是跳转到微信内的目标小程序，需要准确的目标 AppID、页面路径、参数及真机验证；不要用任意网页链接冒充已打通。

## 原生与云端当前边界

- 原生六页：`home`、`routes`、`detail`、`booking`（预约咨询，不是收款结算）、`mine`、`privacy`。
- 真实 AppID 已在本地配置；上传私钥只做过本机格式检查，不证明平台授权、白名单、微信编译或预览成功。
- `miniprogram/config.js` 仍为 `mode: 'preview'`，开发／体验／正式云环境 ID 均为空；正式隐私正文、版本和客服电话未配置。体验／正式环境不得回退到参考数据。
- `wufangApi` 只有四个动作基础：`login`、`listRoutes`、`getRoute`、`createInquiry`。调用契约是 `{ action, payload }`，响应为 `{ ok: true, data }` 或 `{ ok: false, code }`。
- 身份取自服务端 `cloud.getWXContext()`，不信任客户端传入的 owner／角色／状态。公开路线只返回已批准且字段完整的白名单内容。
- 咨询基础有校验、隐私版本、幂等、重试和限流；它保存咨询，不生成可收费订单，也不锁库存。
- 数据库方案默认禁止客户端直接读写，仍必须在每个云动作中检查资源归属和业务角色。禁止客户端直写不能替代服务端权限检查。
- 未登录腾讯云创建资源、未购买套餐、未部署函数。云控制台／微信公众平台不等于旅游运营业务后台。

### P2：真实库存、订单、支付退款

- 所有交易金额服务端计价、整数分；展示价单位元与接口单位分明确转换。

- 支付由商户接入，客户端 `requestPayment` 成功不等于到账。服务端验签／校验 AppID、商户、金额，查单及处理重复／延迟通知。
- 支付回调晚于锁位过期要有明确异常处理、恢复或退款和告警，不能忽略到账。
- 全额／部分退款限于实际支付额；退款状态和是否释放名额分开处理。定金、尾款、优惠与退款规则必须由运营确认，不自行猜测。
- 用获授权的小额真实支付与原路退款验证闭环；不能用演示按钮作为支付验收。

### P3：验收、审核、发布与运营

- 微信 iOS／Android 真机、弱网、权限拒绝、支付未知状态、重复请求及数据隔离验收。
