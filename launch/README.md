## 推进顺序

```text
H5 体验确认（已有）
       ↓
本地原生／云基础与上线准备包（本轮） ← 当前
       ↓
甲方授权与资料确认 ─┬─ AppID / 开发者 / 云环境
                    └─ 资质备案 / 团期库存 / 商户 / 条款素材
       ↓
交付方完成原生迁移 + 后台 + 库存订单 + 社区 + 支付退款
       ↓
云联调 → 微信真机 → 小额真实支付退款 → 备份恢复
       ↓
甲方验收授权 → 微信审核 → 发布 → 日常运营
```

补齐权限不能跳过工程；编译成功不等同于审核通过。

## 本轮准备

- 隔离开发／体验／正式环境，正式版本不回退到测试数据。
- 去除模拟登录成功、咨询保存成功；云端失败提示并保留表单。
- 咨询校验、防连点、重试幂等及服务端限流；隐私未确认禁止提交。
- 云函数从微信可信上下文取得身份，不信任客户端 owner／状态／价格。
- 数据库默认拒绝客户端读写；公开路线返回白名单，未审核／资料不完整路线不上架。
- 原样转换既定 Logo、纳入现有封面；没有重新绘制品牌标志。
- 自动检查、发布拦截、资料模板、接口规范、验收与发布／回滚步骤。

按 harden 要求补了失败、空白、重试与并发提交状态，没有将基础补齐误写为全功能生产实现。

## 交付方仍需完成

1. 原生迁移：主入口及探索、社区、团期筛选、行程、结算、订单、退款，保留已确认设计；验证视频、地图、3D 与降级。
2. 运营后台：一个管理角色维护路线、团期、价格、线下报名、内容审核、退款。微信公众平台／云控制台不等于旅游业务后台。
3. 交易：服务端计价、30 分钟名额锁定、不超卖、回调验签、查单、超时释放、原路退款、审计与对账。
4. 社区：投稿 → 云端内容检查 → 团队审核 → 公开；草稿／拒绝内容隔离，授权、举报与删除闭环。
5. 安全运维：SDK 依赖风险、权限复核、监控、备份恢复、运营培训。
6. 实际微信验证。本机目前没有微信开发者工具，尚未原生编译、上传体验版或微信真机验证。

甲方资料齐备不能自动消除这些工程差距。

## 检查与阻断

```sh
npm run check:miniprogram
npm run verify
npm run check:release
```

报告在 `qa-output/miniprogram-local.json`、`qa-output/miniprogram-release.json`，不上传到小程序。

静态通过只说明本地基础可检查。严格检查对测试 AppID、缺云环境／政策／原生功能／真实验收、安全风险返回失败。不得删除门槛、改名冒充验收或用 H5 代替真支付证据。

在关键授权与业务规则明确前，不购买资源、不收取真实款项、不导入真实旅客信息、不将未验收版本送审。下一步需要云环境、开发者／上传授权与范围确认；不需要再次发送 AppSecret 或私钥。
